# v2.5.2 Local Review and Release Acceptance

## Found and fixed in this review

### [P2] Sync the root dependency lock file

The newly added `package-lock.json` still recorded 2.0.0, and was missing `jose@6.1.3` and `undici@8.11.2`, which `package.json` already declares. `npm ci --ignore-scripts --dry-run` actually returned EUSAGE, so a clean checkout could not install from the lock file. The root lock file has been regenerated, and the 2.5.2 version numbers of the three npm packages and of Rust/Tauri have been synced. The standalone frontend and desktop lock files keep their original dependency versions and platform metadata.

### [P2] Restore read-only file permissions after a successful rollback

The permission retry in `src/updater.js` did not restore the previous permissions after a successful copy. The existing regression only verified the old bytes and the failed-retry path, missing the success path. After adding an assertion for the original permissions, the failure was reproduced on Windows; it passed once a `chmodSync` after success was added. When the copy fails, the original permissions are still restored, the existing file is preserved, and a rollback failure is reported.

### [P2] Wire the LAN regression into the default tests

The standalone service added a LAN relay and a 523-line regression script, but the default test entry point did not call it. A `standalone-lan` suite has been added, included in both contributor and full tests, to prevent the default CI from missing the new network entry point.

## Real upstreams and remaining boundaries

On 2026-10-18 00:33 (Asia/Hong_Kong), two ordinary public API requests to the current `/inference/v1/chat/completions` both returned HTTP 403, classified as `LANE_LOCKED`. The models were `space-bunny-free` and `deepseek-v4.1-flash-free`, and the upstream explicitly stated that the free tier is only for use within OpenCode. This version cannot promise that anonymous channels will recover, and protocol substitute tests are not used in place of verifying real vendor availability.

EAC's 60-second cutoff with no valid output will still terminate long periods of silent computation; account channels have not had per-vendor real-account inference acceptance. The Windows installer has no Authenticode signature. macOS/Linux had no real-machine acceptance or install artifacts in this round, and the new macOS PR #421 is kept for separate handling.
