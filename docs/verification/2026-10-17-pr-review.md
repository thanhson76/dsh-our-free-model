## Cross-Review Corrections

- Login is bound to the connection that actually dispatched the request, fixing the erroneous cancellation of a new connection's login within the 500 ms readiness detection window; state results, failure retries, and post-uninstall results from old connections are all isolated.
- Same-connection polling is ordered by the last published successful request: valid results from slow requests are preserved, while late old responses that would overwrite newer results are rejected; includes a deterministic regression for 45-second polling overlap.
- Named tool calls also refresh the EAC progress timer before arguments arrive, without additionally fabricating streaming deltas; duplicate or unnamed metadata does not renew it. The recovery regression is 129/129, and the stream error checks for the three protocols are 80/80.
- Early classification failures for Chat, Responses, and Messages all preserve CORS, so the browser can read the real HTTP status, error code, and retry hints.

## Boundaries That Must Be Preserved

1. The default full suite is not fully green. The candidate's runtime bytes have changed, and the old signature manifest no longer describes them; the public key was not modified, the old signature was not copied, and verification was not skipped. **The current main cannot be pushed directly as an online upgrade source.** The signature manifest, integrity, and catalog revision must subsequently be updated following the existing authorized process.
2. The measured npm latest is still 2.1.0; 2.5.1 has not been published to that registry. The same-named npm package is not this repository's trusted release channel; the installation docs have been changed to a trusted local tarball, and a measured local update does not mean online distribution has been updated.
3. The local candidate reuses version number 2.5.1, solely for this verification; the installer has not been released.
4. Real inference has not been completed vendor by vendor for all account channels' real accounts/quotas/login environments, and macOS/Linux have not been verified on real machines either. Stub protocol tests or a single upstream success cannot be interpreted as all providers being continuously available.
5. #398 introduces an explicit NO_PROGRESS failure when EAC makes no valid progress for a continuous 60 seconds; automatic retry and switching stop, and legitimate but longer silent computation will likewise trigger this rule.
6. The final live blocking differs from the upgrader's GitHub API rate limiting: the inference upstream explicitly requires the OpenCode client only. The plugin truthfully returns 403 / LANE_LOCKED rather than a blank success; this upstream admission issue has not yet been resolved.
