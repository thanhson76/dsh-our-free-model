# 2.5.3 Emergency Hotfix Acceptance

The baseline is remote main `8c2c0f1e3a1caf5cb682704a576d36a449a6780d`, on the separate branch `hotfix/v2.5.3`. This round only removes the EAC 60-second no-valid-output deadline added in 2.5.2, and synchronizes the 2.5.3 version and installation documentation; no other local feature fixes still awaiting final review were brought in.

## Changes

- Removed the `progressTimeoutMs` default value and the Adapter's progress timer, so silent queueing, heartbeats, usage frames or gaps between output no longer produce `NO_PROGRESS`.
- `progressTimeoutMs` in old configurations is ignored. Caller cancellation, handling of actual transport disconnects and the existing recovery strategy are retained.
- Replaced the previous regression that “should fail at the progress deadline” with verification that a request completes normally after waiting, that the same physical request is not submitted twice, and that a lane does not switch on its own because of silence; added a regression that the default 60-second timer is not created.
- OpenCode's `src/upstream.js`, request transport, probing rules and channel fingerprint source were not changed. Admission refusal by an anonymous upstream is outside the scope of this fix.
- A real local upgrade log reproduced `packages/desktop/src-tauri/target` being backed up to the C drive and triggering `ENOSPC`; a top-level `packages` exclusion was added, so upgrade, cleanup and rollback must not traverse or copy the standalone product tree, and the original build cache stays on the D drive.
