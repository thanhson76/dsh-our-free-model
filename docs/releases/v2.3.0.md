# Our Free Model 2.3.0

## What's New

- The free model lane migrates to the new `/inference/v1` request path, adding the session identifiers, tool fingerprints and client attribution handling the upstream requires.
- The free lane persists its session mapping, so the original session continues after a service restart; an upstream `FreeTierError` is recognised as a lane lock and no longer misleads the user into signing in again or clearing the model catalogue.
- The plugin upgrade page becomes its own navigation entry, showing the current version, the on-disk version, upgrade progress and failure reasons; the original settings page keeps its settings functions and no longer renders the upgrade panel a second time.
- The plugin, the standalone local service and the Windows desktop shell are all upgraded to 2.3.0.

## Upgrade and Restart

### DSH Plugin

Check for and install 2.3.0 under Settings → Plugin upgrade. End any requests still generating before upgrading; after installation, fully exit DSH desktop (including the tray) and restart it, then confirm the version number and the free model catalogue.

### Standalone Local Service

Stop the old service first and back up the program directory and data directory, then replace the program files. Start the new version with the original data directory, sign in through the management link printed at startup, and confirm the page shows 2.3.0. Do not run two instances sharing one data directory at the same time.

### Windows Desktop App

Choose "Exit" from the tray menu, then install the new full installer and reopen the app. Do not copy just the executable; the installer includes the standalone service and runtime resources.

## Data and Rollback

The upgrade keeps the existing configuration, accounts and statistics. The free lane migrates and reuses the local session mapping; if the service cannot start, stop the current instance first, then restore the old full program and the original data-directory backup.

Rollback: the plugin uses the full plugin backup from before the upgrade, the standalone service restores the old program directory, and the desktop build restores the old full installer. Do not handle an upgrade failure by deleting the data directory, lock files or account credentials.
