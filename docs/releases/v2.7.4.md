# v2.7.4 Plugin Release

This release is DSH-plugin only; the desktop installer and standalone product versions remain as they were. This is the release from the full issue audit of 2026-10-31:
19 community fix PRs and 8 local fixes are merged in, all verified locally first and only then merged.

## Forwarding and Streaming Protocols

- Streaming `tool_calls` frames carry id/name only on the first frame, indexes are numbered consecutively from 0, and bare index frames with no function are no longer emitted (#621, #452).
- Each frame of a Responses stream gains the required sequence_number (#548).
- When upstream returns a 5xx with an empty body, it states clearly which layer failed, and notes that the request carried an image (#549).
- Tool arguments are judged separately for syntactic invalidity and length truncation (#474).
- Keepalive comment frames no longer extend the idle deadline indefinitely; the idle clock is wound only by real data (#460).
- `ChannelNetworkError` gains a code, so transient network failures can be retried normally (#587).

## Sessions, Aggregation and the Model Catalogue

- Concurrent sessions are isolated; turns with no sessionId no longer share a global session (#532).
- A silent candidate on a combo chain no longer blocks the whole chain (#630).
- The aggregate channel gains modelsUrl, fixing the "declares no model listing" false alarm (#682); 16 providers gain verified modelsUrls (#538).
- A `-vl` segment is treated as a vision marker, so the family rules no longer mark vision variants as pure text (#458).
- Gemini tool schemas strip empty-string enum members, avoiding upstream 400s (#251).

## Account Channels and the Management Side

- Trae usage frames read the cache-hit field, so cacheReadTokens is no longer permanently 0 (#701/#213).
- The channel account "Test" tests a model along the candidate chain and returns the elapsed time, and a Loomy probing branch is added (#681).
- After a channel model is hidden, the session picker refreshes (#644).
- The management side's model refresh API returns each source's result (#670).
- EAC sign-in supports the Windows system proxy (#620); browser startup resolves execFile at call time, so the offline stub can take effect.
- openai-gateway tool-call frames are compatible with old and new DSH kernels (#610).

## Workbench and Client

- Drift of the Windows reserved port range (winnat/Hyper-V/WSL) across restarts no longer leaves the workbench permanently at "startup failed"; an occupied port takes a new port and persists it (#688).
- The collapse button is no longer lost in the instant the workbench expands, and Esc inside the iframe also collapses it (#700).
- The announcement clean-up hook is moved before the early return, fixing the React hooks order (#631).

## Security and Upgrades

- On Windows, the private-file 0600 promise actually takes effect through icacls (#456); the permissions module is merged into `open-external.js`, and the release package keeps its 80-file budget.
- `undici` is now loaded on demand; when undici is missing, the proxy path throws a clear error instead of silently connecting directly, avoiding leaking proxy users' IPs.
- Installs managed by pnpm are refused in-app upgrades and handed back to the original installation method for maintenance (#335).
- The management boundary redacts excluded channel names in third-party copy, so new entries in the upstream market no longer break the invariant.

## Installation and Verification

Before release, the full release suite passed: production signing, the 8/8 legacy upgrade regressions against the original 1.3.1 and 2.5.9, generated-artefact consistency checks,
and catalogue-record and byte consistency checks. The release tarball is built from the LF bytes of a pinned commit; its 80 runtime files match the formal signed manifest byte for byte,
and the entry point loads after unpacking. After release, fetch verification of the four default update sources was completed as an installed user (live-audit), and the CDN was refreshed over the whole tree.

Self-installed legacy users can check for updates on the plugin upgrade page; host-managed installs should update the trusted tarball through the original installation method;
for a manual install, use this release's full plugin package and keep the original user data directory — do not replace only the entry files. The tests only access local services,
and do not mean every network environment or real model upstream has been verified.

## Rollback

The upgrader continues to perform the original signature, file-size, SHA-256, backup and rollback checks. For a manual rollback, use the previous version's trusted plugin package,
and keep configuration, accounts and statistics.
