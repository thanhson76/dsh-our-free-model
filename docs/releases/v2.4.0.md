# Our Free Model 2.4.0

## What's New

- The free lane's fingerprint is redone for the upstream **OpenCode v2 client** in effect since 2026-10-14. Four kinds of characteristic change together, and missing any one of them means
  `403 FreeTierError`:
  - The User-Agent becomes `opencode/latest/2.0.26/cli` (the old `opencode/1.18.x` is rejected by upstream by name);
  - The session headers are completed with `x-session-affinity` / `x-session-id`, carrying the same value as `x-opencode-session` /
    `x-opencode-session-id` across all four headers; the v1-only `x-opencode-request` is **no longer** sent;
  - The tool gate becomes the two names `read` and `shell`, and the description and parameter schema must match the official client
    word for word — the v1-era "stub tools + placeholder properties" approach no longer works;
  - `tool_choice: 'none'` is never sent (upstream returns 403 on sight); continuation turns instead suppress tool calls through the instruction body.
- The caller's tools are **kept as-is** (including case variants such as `Read`/`Bash`). If `read`/`shell` happens to be used with a different definition,
  that tool is renamed to `<name>_client`, and same-named calls in the history and `tool_choice` are rewritten in sync, then restored on the response side
  to the caller's name — the plugin's own lane and the vendored channel pack behave identically on both sides.
- Added `scripts/opencode-parity-test.mjs`: it asserts item by item that the two sides' fingerprints (gate names, word-for-word definitions, UA, header set, aliases,
  history rewriting, `tool_choice`, level convergence) do not drift, and it is wired into `npm run test:contributor`.
- Added a "Recommended projects" page: two cards point to EAC-Desktop and EAC-Pack respectively, with their Star / Fork / most-recent-commit counts fetched live
  from GitHub; if they cannot be fetched, the whole block is not shown, and placeholder numbers are never used. The page also joins the tab-persistence list, so a refresh stays on
  the same page.
- The aggregate channel registry removes the OpenCode keyless-pool row: it requires a per-request session id, the v2 client UA and a set of official tool
  declarations, which the aggregate lane's generic transport has nowhere to carry; listing it anyway would only add a picker row that can never connect; those 10 models
  are provided natively by the free lane. The registry therefore stands at **75 providers**.
- The plugin, the standalone local service and the Windows desktop shell are all upgraded to 2.4.0.

## Upgrade and Restart

### DSH Plugin

Check for and install 2.4.0 under Settings → Plugin upgrade. End any requests still generating before upgrading; after installation, fully exit DSH desktop
(including the tray) and restart it, then confirm the version number and the free model catalogue.

### Standalone Local Service

Stop the old service first and back up the program directory and data directory, then replace the program files. Start the new version with the original data directory, sign in
through the management link printed at startup, and confirm the page shows 2.4.0. Do not run two instances sharing one data directory at the same time.

### Windows Desktop App

Choose "Exit" from the tray menu, then install the new full installer (`Our.Free.Model_2.4.0_x64-setup.exe`), and reopen
the app. Do not copy just the executable; the installer includes the standalone service and runtime resources.

### macOS Desktop App

No macOS installer was built this time (the build machine is Windows). macOS ARM64 users should keep using the v2.3.0 DMG, or
use the standalone local service CLI directly; this version's free lane changes apply to the standalone service as well.

## Data and Rollback

The upgrade keeps the existing configuration, accounts and statistics. The free lane continues to reuse the local session mapping; the shape of the session id is unchanged — upstream
only added a "the counter must be small" constraint, and the minter resets to zero every millisecond, so it is naturally satisfied.

Rollback: the plugin uses the full plugin backup from before the upgrade, the standalone service restores the old program directory, and the desktop build restores the old full installer.
Do not handle an upgrade failure by deleting the data directory, lock files or account credentials.
