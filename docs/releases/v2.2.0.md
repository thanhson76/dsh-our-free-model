# Our Free Model 2.2.0

## What's New

- The EAC service has migrated to a new server; after updating and restarting you will use the new service.
- The GitHub authorization and Star status confirmation flow has been improved, keeping the original account management entry.
- The DSH plugin, the standalone local service and the Windows desktop app are provided, all unified at version 2.2.0.
- The desktop app has a built-in runtime, improving startup, window restoration and service clean-up on exit.

## Upgrade and Restart

### DSH Plugin

Before upgrading, end any requests still generating and back up the plugin directory and user data. Check for updates through the plugin update entry, install 2.2.0, then fully exit DSH desktop (including the tray) and restart it. Open Our Free Model to confirm the version; if EAC says authorization is required, redo the GitHub sign-in and Star status confirmation.

### Standalone Local Service

Stop the old service first, back up the original program directory and data directory, then extract the new version into a new directory. Start it with the original data directory, and avoid running two copies of the service at the same time. Open the management link printed at startup and confirm the version is 2.2.0. The Windows portable package uses the bundled start script and needs no separate Node installation.

### Windows Desktop App

Choose "Exit" from the tray menu first, then install the new full installer and reopen the app. Merely closing the panel hides it to the tray and does not stop the service. Do not copy the EXE alone in place of the full installer.

## Data and Authorization

The upgrade keeps the existing configuration and user data. After the server migration, an old EAC authorization may require signing in again. If authorization cannot be completed, start the sign-in again from inside the app; do not keep using a previously saved login page.

## Rollback

Stop all current services before rolling back, and back up the data again.

- DSH plugin: restore from the full plugin backup kept from before the upgrade, then fully exit and restart DSH.
- Standalone service: restore the old program directory and start with the backed-up data directory.
- Desktop app: exit from the tray, then restore the old full installer; if the old version cannot read the new data, use the data backup from before the upgrade.

Rolling back to the old program does not guarantee the old server is still usable; if the old EAC service is unavailable, upgrade back to 2.2.0. Do not resolve upgrade problems by deleting account data, unknown lock files or force-killing unrelated processes.
